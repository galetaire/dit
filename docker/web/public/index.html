Set up your devices

Pick the setup that matches your network. Addresses are filled in from your Umbrel.

Whole home network (router)

Recommended

Every device on your Wi-Fi uses Dit, with nothing to change on each one.

  1. Give your Umbrel a fixed address in your router (often called "DHCP reservation" or "static lease"), so it does not change.
  2. In the router's DHCP or LAN settings, set the DNS server to your Umbrel's IP. Leave the secondary DNS empty: a second server would answer some lookups without Handshake.
  3. Reconnect your devices to Wi-Fi so they pick up the new setting.

Needs the "DNS server for my network" mode. If your Umbrel is off, devices lose DNS until it is back or you undo the router setting.

Android phone

Use the router setup, or set one Wi-Fi network by hand.

  1. At home: follow the router setup, or set it for one Wi-Fi network: Settings → Network & internet → Internet → your network → edit → Advanced → IP settings: Static, and enter your Umbrel's IP as DNS 1.
  2. Settings → Network & internet → Private DNS must be Off or Automatic. A provider name there (for example dns.google) bypasses Dit.
  3. In Chrome: Settings → Privacy and security → Use secure DNS → Use your current service provider, or turn it off.
  4. Away from home: use the Tailscale setup. Android has no DNS setting for mobile data.

Open Handshake names in the browser with a trailing slash, for example mysite/, so the browser does not search for them instead.

Anywhere, with Tailscale

Your devices use Dit on any network, without opening ports on your router.

  1. Install the Tailscale app on your Umbrel and on your phone or laptop, and sign in to the same account.
  2. In the Tailscale admin console, open DNS → Nameservers → Add nameserver → Custom, and enter your Umbrel's Tailscale IP (100.x.y.z).
  3. Turn on Override DNS servers.
  4. With Tailscale connected, the device resolves Handshake names through your Umbrel wherever it is.

Needs the "DNS server for my network" mode: Tailscale nameservers always use port 53.

Behind Pi-hole

  1. Choose "Upstream for Pi-hole or AdGuard Home" in Listening mode.
  2. In Pi-hole: Settings → DNS → untick the listed upstream servers, and add the custom server 127.0.0.1#5300.
  3. Untick "Use DNSSEC": Pi-hole checks answers against the regular internet's root key and rejects Handshake names. Dit already validates them.
  4. Untick "Never forward non-FQDN A and AAAA queries", so bare names like mysite/ reach Dit.
  5. Save. Pi-hole keeps blocking ads and sends every lookup to Dit.

Behind AdGuard Home

  1. Choose "Upstream for Pi-hole or AdGuard Home" in Listening mode.
  2. In AdGuard Home: Settings → DNS settings → Upstream DNS servers, replace the list with 127.0.0.1:5300.
  3. Apply. AdGuard Home keeps filtering and sends every lookup to Dit.
Never forward port 53 Don't forward port 53 from your router to your Umbrel. A resolver open to the internet gets abused for attacks on others.

Secure sites

Many Handshake sites prove their HTTPS certificate with a DNS record (DANE) instead of a certificate authority. Browsers don't check that, so Dit's proxy checks it for them.

Without proxy settings Beta

Off

Devices that use Dit as their DNS server open DANE sites without the auto-config proxy: only the certificate is needed. Dit answers those names with an extra address of its own on your network, because umbrelOS already uses port 443 on the Umbrel's address.

When it is on, devices can drop the auto-config proxy setting. Devices that keep it still work, and Windows needs it for single-word names (see Windows below). Turning it off removes the extra address again.

Android (Chrome)

Once per phone, and the proxy once per Wi-Fi network.

  1. On the phone, open http://your-umbrel:9053/dit-dane.crt in Chrome to download the certificate.
  2. Settings → Security & privacy → More security settings → Encryption & credentials → Install a certificate → CA certificate → Install anyway, and pick dit-dane.crt.
  3. Settings → Network & internet → Internet → your Wi-Fi → edit → Advanced → Proxy: Auto-config, and enter http://your-umbrel:9053/proxy.pac as the PAC URL. Save. Skip this step when "Without proxy settings" above is on.
  4. Open a Handshake site that uses DANE, for example nathan.woodburn/. It loads without a certificate warning.

Chrome trusts the certificate; most other Android apps ignore certificates you install yourself. The proxy setting only applies on that Wi-Fi network. Menu names differ a little between phone brands.

Windows (Chrome and Edge)

  1. Download the certificate, open it, and choose Install Certificate → Current User → Place all certificates in the following store → Trusted Root Certification Authorities. Check that the fingerprint matches the one on this page.
  2. Settings → Network & internet → Proxy → Use setup script → Set up, and enter http://your-umbrel:9053/proxy.pac as the script address. Save.
  3. Restart the browser.

Keep the setup script on Windows, even with "Without proxy settings" on: Windows never looks up single-word names like mysite/, so without the script only names with a dot (www.mysite/) open. The script sends every Handshake name to Dit's proxy, which looks it up itself.

Firefox

Firefox has its own DNS and its own certificate store, so it needs two settings Chrome doesn't.

  1. Turn DNS over HTTPS off. Otherwise Firefox asks a public resolver, which doesn't know Handshake names ("We're having trouble finding that site"). Android: Settings → Privacy and security → DNS over HTTPS → Off. Windows: Settings → Privacy & Security → DNS over HTTPS → Off.
  2. Trust Dit's certificate. Android: install it in Android as above, then Settings → About Firefox → tap the Firefox logo 5 times → back in Settings, Secret Settings → Use third party CA certificates. Windows: Settings → Privacy & Security → Certificates → View Certificates → Authorities → Import, and tick "Trust this CA to identify websites".
  3. For the proxy, Windows: Settings → Network Settings → Automatic proxy configuration URL, with the address above. Android: Firefox uses the Wi-Fi proxy setting.

How it works

  1. The auto-config file sends only Handshake names to the proxy. Every regular site goes straight to the internet, as before.
  2. The proxy looks up the site's TLSA record through Dit, verified with DNSSEC, and checks the site's certificate against it.
  3. If it matches, the proxy hands your browser a copy signed by Dit's certificate. If not, the page doesn't open.

Handshake sites without DANE are passed through untouched and behave as they do today.

Keep it on your network Don't forward port 9053 from your router. The proxy only answers devices on your local network, but it should never face the internet.
